# Content data layer

All rules content is static JSON bundled with the app. Only user data goes in the database.

## Packs

| Pack | Folder | Default | What it holds |
|---|---|---|---|
| `srd` | `content/srd/` | on | SRD 2.0: everything except the campaign frame chapter |
| `srd-frames` | `content/srd-frames/` | off (per-character toggle, decision D3) | Witherwild Campaign Frame and Supplemental Campaign Mechanics (pp. 184–205) |
| `hb-<uuid>` | user account | off | Homebrew. Same schemas, `source.kind = "homebrew"`, never bundled |

Each pack folder holds:
- `pack.json`: id, version, attribution, modification statement
- `data/<type>.json`: one file per entry type

## Commands

```bash
npm run content:extract -- path/to/DH_SRD_2_2026_08_25.pdf   # PDF -> content/srd/raw/ (downloads the PDF if no path)
npm run content:parse        # raw -> content/srd/data, content/srd-frames/data
npm run content:validate     # schema + links; add homebrew files as args to check them too
npm run content:jsonschema   # content/schema/pack.schema.json for homebrew authors
npm run content              # parse + validate + jsonschema
npm test                     # includes content completeness and validator tests
```

The parse is deterministic. Running it again on unchanged input gives an empty `git diff`.

## Checking the parse against the source

The raw text is kept beside the parsed JSON:
- `content/srd/raw/srd-2.0.txt`: the whole PDF, one PDF line per line, with table cells split by TAB and `@@PDFPAGE n@@` page markers.
- `content/srd/raw/sections/<type>.txt`: only the pages each entry type came from.
- `content/srd/raw/srd-2.0.lines.json`: what the parser reads (font size, position, cells, bold/italic marks).

Every entry has `source.page` (and `pageEnd` if it spans pages).

## Ids, text and tags

- **Ids** are `<pack>/<type>/<slug>`, e.g. `srd/class/warlock`. There is no version in the id, so characters survive pack updates.
- **Text** is light markdown: `**bold**`, `_italic_`, lists, tables.
- **Inline tags:**
  - `{{term:<slug>|label}}` links a glossary term, generated by `scripts/parse/glossary.ts`.
  - `{{ref:<entry-id>|label}}` links another entry.
- **Glossary terms** are a curated list in `content/srd/glossary-terms.json`. Each term's tooltip summary is a verbatim sentence from the rules section it points at.

## Errata (decision D7)

`content/srd/errata.json` lists every change we make to the SRD text, with page and reason. Each erratum must match exactly once, or the parse fails. The pack's `modifications` field (shown with the attribution) says text was reformatted and errata applied.

## Schema notes (changes from the proposal)

- **`adversary.attack.modifier`** is a signed string (`"+2"`, `"+2d4"`). One adversary uses a die.
- **`adversary.thresholds`** can be `null` (minions). Either side can also be `null` (Octopus, p. 105: `3/None`).
- **`adversary.hp` and `adversary.stress`** can be `null` (Spellbound Armor, p. 110: `Stress: None`).
- **`weapon.trait`** can be `"spellcast"` (arcane-frame wheelchairs use the subclass Spellcast trait).
- **`beastform` stats** are `null` for upgrade forms (Legendary/Mythic Beast), whose stats come from the base form.
- **`feature.kind`** adds `"evolution"` (Hope & Fear adversaries).
- **`progression.advancements[].slots`** is `null`: SRD 2.0 doesn't state slots per tier (see PROGRESS.md).
- **Classes have no `suggested` traits or gear:** SRD 2.0 doesn't include them.
